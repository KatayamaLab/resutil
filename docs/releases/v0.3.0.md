## Features

- Offline mode (#48): when storage cannot be reached because the network is unavailable,
  `@resutil.main()` switches to offline mode, runs the experiment, and keeps results locally.
  Run `resutil push` later to upload them.
- Japanese messages: CLI, TUI and runtime messages are available in Japanese.
  Select the language with `RESUTIL_LANG=ja` or `RESUTIL_LANG=en`; by default it follows
  `LC_ALL`/`LC_MESSAGES`/`LANG`, then the OS language.

## Fixes

- Server credentials are no longer refreshed when storage is constructed; they are refreshed
  on the first request. An expired token no longer prevents offline startup.
- A rejected refresh token is reported as an authentication error with a `resutil login` hint.
- Dependency experiments are resolved before the experiment directory is created; when they
  cannot be obtained, execution stops with an explanatory message and no empty directory is left.

## Compatibility

- **Behavior change:** a network failure during the final upload after successful computation
  no longer exits with an error. A message with a `resutil push` hint is printed and the
  exit status is 0. Authentication errors and non-network upload failures (e.g. HTTP 5xx)
  still fail as before.
- Authentication errors (401/403, rejected refresh token, missing or mismatched credentials)
  still stop execution at startup; run `resutil login`.
- Checkpoints still attempt to upload while offline and may wait for connection timeouts.
- CLI commands such as `resutil push`/`pull` still require a network connection.

## Validation

104 regression tests; Black, Flake8, mypy, and package-build checks.
CI on Linux and Windows with Python 3.10 and 3.12.
