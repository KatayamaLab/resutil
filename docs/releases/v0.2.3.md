## Fixes

- Prevent missing local experiments from overwriting remote results with empty archives.
- Validate experiment names and deletion paths; require confirmation before deletion.
- Fix legacy dependency paths, nested and cyclic transfers, and hidden transfer errors.
- Detect modified results after checkpoints and retry failed final uploads.
- Preserve function return values, failure exit codes, and the working directory.
- Refresh server credentials during long runs, bind credentials to their server, and encode API paths.
- Validate login callback state and tolerate unrelated callback requests.
- Update dependency references when renaming comments; restore local metadata if renaming fails.
- Fix Google Drive pagination, folder selection, concurrent access, and archive updates.
- Avoid Unicode logging failures with legacy Windows output encodings.
- Handle Git repositories without commits and record untracked files and deletions.
- Improve TUI network-error handling, UTF-8 support, timezone selection, and directory-name collisions.

## Compatibility

- Server login requires a resutil-server deployment that preserves the login state.
  Update the server before upgrading clients. Existing matching credentials can still be refreshed.
  See `docs/server-login-state.patch` and `docs/review-fixes.md`.
- Comments are limited to 200 UTF-8 bytes.
- `resutil rm` requires confirmation; use `--yes` for scripts.
- `RESUTIL_NO_REMOTE` skips authentication and uploads; `RESUTIIL_REMOTE` remains an alias.
- Experiments without synchronization receipts are conservatively uploaded once.
- `RESUTIL_TIMEZONE` accepts an IANA zone such as `Asia/Tokyo`.
